# Pipe_from_github_JSON_to_Lakehouse_deltaTable
---

## Copy a JSON file from GitHub into a Lakehouse Delta table

This chapter demonstrates a Copy data pipeline that reads `Labdata/emp.json` from the `rritec/Microsoft-Fabric` GitHub repository and appends its rows to the `raw.tgt_github_emp_json` table in a Lakehouse.

> The connection IDs and workspace/Lakehouse IDs in the example JSON are specific to one Fabric environment. Use the corresponding IDs and connection in your workspace.

---

## 1. Prepare the source JSON

The source file used in this example is:

- Repository: `rritec/Microsoft-Fabric`
- Branch: `main`
- File: `Labdata/emp.json`
- GitHub relative URL: `rritec/Microsoft-Fabric/refs/heads/main/Labdata/emp.json`

The file contains an array of employee objects. Ensure the REST connection can access the raw GitHub content host. For a private repository, configure access in the connection rather than embedding credentials in the pipeline.

---

## 2. Create the pipeline

1. Open [Microsoft Fabric](https://app.fabric.microsoft.com) and go to your target workspace.
2. Select **New** → **Data pipeline**.
3. Name the pipeline `Pipeline_2_Pipe_from_SqlDatabase_to_Lakehouse_deltaTable` to match the supplied pipeline JSON. You can rename it to `Pipe_from_github_JSON_to_Lakehouse_deltaTable` if desired.
4. Add a **Copy data** activity.

---

## 3. Configure the source

1. Select the Copy activity and open **Source**.
2. Choose **REST** as the source type and select or create a REST connection.
3. Configure the connection for the raw GitHub content host, `https://raw.githubusercontent.com/`.
4. Set the HTTP method to **GET**.
5. Set the relative URL to:

   ```text
   rritec/Microsoft-Fabric/refs/heads/main/Labdata/emp.json
   ```

6. The supplied configuration uses an HTTP request timeout of `00:01:40`, a request interval of `00.00:00:00.010`, and enables RFC 5988 pagination support.

---

## 4. Configure the Lakehouse sink

1. Open **Sink** and choose **Lakehouse**.
2. Select the Lakehouse connection and the `Tables` root folder.
3. Set the destination schema to `raw`.
4. Set the destination table to `tgt_github_emp_json`.
5. Set write behavior to **Append** and partition handling to **None**.

---

## 5. Configure mapping, publish, and run

1. Configure or preview the source schema.
2. Select **Mapping** and confirm that the JSON fields map to the destination columns. The supplied translator flattens nested fields using `.` as the delimiter and does not treat arrays or structs as strings.
3. Save and publish the pipeline.
4. Run it.
5. Verify that records from `emp.json` were appended to the `raw.tgt_github_emp_json` Lakehouse table.

---
